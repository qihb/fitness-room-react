# 计划驱动开发（fitness-room-react）

本仓库所有**开发计划、功能实现、改造重构**任务，均按下述流程落地。

## 项目锚点

- **规范来源**：仓库根 `AGENTS.md`（技术栈、目录约定、编码规范、边界、协作流程）。执行前先读。
- **计划文件**：`docs/plans/YYYY-MM-DD-<slug>.md`。
- **校验命令**：`pnpm exec vp check`（格式化 + lint + 类型）、`pnpm exec vp test`。
- **禁止修改**：`dist/`、`node_modules/`、`pnpm-lock.yaml`，以及 `AGENTS.md` 中 VITE PLUS 自动生成段。
- 只用 pnpm；组件用函数组件 + `.tsx`；样式 Tailwind 管布局、antd 管交互。

## 铁律

1. **先计划后编码**：先产出简要计划，等用户**明确确认**后再动手。禁止"出计划即写代码"。
2. **计划要简要**：控制在约一屏，只列目标 / 步骤清单 / 涉及文件 / 关键决策；不贴大段代码、不写长篇背景。
3. **按步执行**：用户确认后，由用户**指定**要执行哪几步，只做被指定的步骤，不擅自扩大范围。
4. **逐步交付**：每完成一步就更新落地文档（`- [ ]` → `- [x]`，加备注）并报告结果。
5. **有疑问先确认**：计划阶段遇到需要决策的点，先用问题确认，再写进计划。

## 落地文档格式

```markdown
# <标题> · 落地计划

**目标**：一句话说清要达成什么。
**技术栈**：见 AGENTS.md（可摘相关项）。
**涉及文件**：预计新增 / 修改的文件清单。
**关键决策**：需用户拍板的点；无则写「无」。
**执行约定**：本文件仅为计划；由用户指定步骤后再执行，每完成一步勾选 `- [ ]`。

---

## 阶段 0 · <名称>

- [ ] 0.1 <步骤>
- [ ] 0.2 <步骤>

## 阶段 1 · <名称>

- [ ] 1.1 <步骤>

---

## 当前状态

- 计划待用户确认；确认后按指定步骤执行。
- <已部分执行 / 需保留的变更与备注>
```

## 执行循环

澄清 → 写 / 更新落地文档 → 等用户确认 → 用户指定步骤 → 执行该步骤 → 勾选并更新「当前状态」→ 报告 → 回到"用户指定步骤"。

## 交付报告

每步完成后用一句话说明：做了什么、改了哪些文件（`file:///` 链接）、验证结果（`vp check` / `vp test`）、下一步待用户指定。
